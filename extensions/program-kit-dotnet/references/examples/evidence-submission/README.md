# Evidence submission: finite semantic example

This fictional review desk demonstrates one actor preparing a bounded text file,
confirming immutable title/date/content, accepting a retained server-issued identity,
and reconciling an accepted-but-lost response. It is an example for ordinary coding
and review, not another scaffold generator, authentication system or consumer approval.

Export through the existing installed asset owner:

```powershell
python .specify/extensions/program-kit-governance/scripts/asset_sources.py --repository . --component program-kit-dotnet --subtree references/examples/evidence-submission
```

Use the selected native project/composition generators to establish the accepted
Core, implementation, API and provider owners. Copy each source into its owner and
adapt the fictional names through ordinary editing. Application code belongs to
the consumer immediately. F4's finite label renderer remains its own supported
adapter; it does not pretend to generate this different domain. Preparation,
qualification, reconciliation and completion still use the existing F2/F3/F4 route.

Canonical engineering rules resolve from `phase-obligations.json`; this recipe
links their realization rather than becoming a second rulebook. In particular,
consult modularity/HTTP ownership, the .NET construction/style overlay, persistence
admission, UI feedback/recovery, and the exact selected publisher knowledge.
Inspect [the scoped ownership review and rejected changes](ownership-review.md)
alongside actual source. It distinguishes structural/runtime failures from
semantic source-review cases that an automated checker cannot certify.

## Owners and actual behavior

| Source | Responsibility |
| --- | --- |
| `Core/` | Valid immutable UTF-8 input, one owning pair of input bounds, business observations and cohesive capability contracts. No transport, DI, EF or dispatcher. |
| `Runtime/` | Actor/identity admission before provider work and feature-owned scoped application registration. The explicit bounded loader is separate from pure deployment construction. |
| `PostgreSql/` | Private EF records/model/JSON, preparation, owner predicates and one atomic conditional acceptance. SQL structure is closed, identifiers come from the actual model/provider quoting and values are bound. |
| `Api/` | Typed native JSON contracts, wire admission/mapping, authorization metadata, request cancellation and activation-time native Options validation. The input contract projects Core bounds. |
| `web/` | Coherent fictional journey, generated-type transport adapter, immutable confirmation, native confirmation/session controls, generation-bound file preparation and retained recovery. |

The application capability executes independently of HTTP. Preparation retains
one immutable packet. Acceptance changes that exact row only while unaccepted;
repeating the same acceptance does not increment its revision. Status lookup
checks the owner and performs no effect. Preparation-response loss can leave an
unaccepted preparation; it is not proof that no allocation occurred. The example
does not supply expiry/retention administration, general retry, distributed
transactions or an arbitrary upload/archive service.

Native options binding remains `AddOptions/Bind/Validate`; an actual shell
initializer observes required options before activation succeeds. No competing
binder is introduced. Infrastructure connection material remains supervisor-owned
in the fixture environment; it is not a generated options literal or an authority
grant. The loader owns no stream disposal, provider/account initialization or paid
permission. No current toolkit deployment-constructor defect was established.

## Integration and proof boundaries

Select the owning runtime/API/provider features directly in shell configuration.
The consumer's selected native authentication/authorization/antiforgery profile,
settings-source inspection, Build/pack, contract registry/export/baseline and
generated-client pipeline remain mandatory where applicable. Never copy the
test-only `Fixture.Identity`, fictional owner header or session projection into
production. Those live under the contributor fixture and supply no login or
provider-session acceptance. Adapt the sample transport to the actual selected
native session/antiforgery owner before production use; the fixture is not that
adapter's qualification. Missing adapters remain actionable limitations.

The contributor fixture compiles four separate actual source owners against the
current qualified dependency set. It activates their real features and native
middleware, then executes real local HTTP and PostgreSQL. Explicit test deployment
uses a different administrator identity; the runtime role receives only its needed
table grants. Runtime registration never creates product schema. Independently
authored SQL and model authority are outside the provider's mapping constants.

The browser consumes an actual native OpenAPI document through the maintained
generator and current strict TypeScript compiler, then uses that emitted adapter
for its requests. An invalid wire type must fail compilation. This is runtime
document/client proof, not a new cold package export or compatibility-baseline
qualification. Existing native settings/Build/export routes remain their owners.

The selected native browser modules execute exact captured current bytes against
fictional session projections. The native UI theme and feedback helpers retain
their existing owners. Forms/Localization's unchanged historical qualification is
preserved separately; this fixture neither replaces their adapters nor claims a
fresh Forms package lookup/browser qualification.

The file example consumes owning input bounds, aborts FileReader on invalidation
or deadline and suppresses late crypto results. Crypto itself is not abortable.
Private drafts/content stay in the disposable fixture. Unknown completion keeps
the original identity; edits cannot silently replace it or dispatch another effect.

The normal entry is the fictional workspace/inbox, not a component gallery.
Its final example home is this maintained subtree; the disposable runnable copy,
screens, tests and navigation remain retained until human review finishes. A real
temporary backend demo must name its final product home and integration/removal
owner in the existing plan/tasks. No new approval artifact is needed.

Run the maintained `validate_coding_seed_native` and
`validate_coding_seed_journey` checks with an explicit affected reason. The former
compiles invalid mapping/registration/lifetime/options/effect/ownership/middleware
controls and requires their independent behavioral failures. The latter retains
desktop/mobile Chromium/WebKit screens and controls, focus/errors, immutable input,
actual response loss and same-identity reconciliation. The review guide names exact
outputs, both streams, snapshots and limits. Source review and human visual/product
review remain independent duties. PostgreSQL proof does not qualify SQLite or SQL
Server; fictional identity is not BFF/Keycloak acceptance; no paid worker is started.

Separate focused scenarios reuse current native domain events, parser/recording SDK
contracts, physical fencing and private runner diagnostics. Independent observers
never own mandatory workflow ordering, and in-process dispatch is not durable
integration. The read-only query counterexample selects no domain-event seed.
