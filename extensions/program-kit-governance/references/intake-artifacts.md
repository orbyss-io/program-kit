# Intake artifact authoring contract

## One authoring source

Keep connected product understanding in ordinary project-intent.md: purpose, actors, journeys,
scope, important domain concepts/roles/entities, lifecycle/policy meaning, decisions and rationale,
provenance, provisional assumptions and an unanswered frontier with owners/triggers/next action.
Use existing rich architecture documents as inputs. A separate intake-authoring.json is not required.

## Bootstrap intake

Historical bootstrap-intake.json may provide useful observations, never current workflow authority.
Do not create or confirm it for the preview route. Record the actual human product confirmation
in readable intent. Separate that decision from constitution ratification and individual ADR
acceptance. No hashes, assessment/closure reports or general confirmation receipt are needed.

## Canonical architecture map

When useful, keep one small language-neutral docs/architecture/architecture-map.json using
architecture-map-v2.schema.json and architecture-map-minimal.json. Stable IDs connect people,
systems, containers, components and meaningful domain boundaries. Relationships state real
responsibility/integration. Optional domain data explains concepts, policies, lifecycles and
unanswered questions; it is not an exhaustive future design requirement.

Optional ADR links use real repository-relative paths and explicit Proposed/Accepted/etc status.
A map catalog records stated decisions; validation cannot grant human consent. Local architecture
representations remain possible. Existing1.1 detailed maps retain their own optional schema/export
contract as input, without converting their old approval fields.

## Write and validate

Author readable intent, constitution and consequential ADRs proportionally. Separate technology
and roadmap documents only when they improve clarity. Explicitly confirm actual meaning with the
human and record it where discussed. Use optional architecture_map.py validate/export for actual
map/reference/projection integrity, product_intake.py inspect for present context, or normal native
Spec Kit commands directly. Each helper enforces its own real inputs, never unrelated phase artifacts.
