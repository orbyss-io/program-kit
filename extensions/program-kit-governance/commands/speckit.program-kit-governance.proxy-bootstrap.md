## Scope

Use only when the user explicitly requests a same-session proxy bootstrap rehearsal. A proxy intake
request alone stops at intake. This extension authorizes local rehearsal work in its disposable
consumer, including bounded compatibility proofs; it supplies no real consumer confirmation,
architecture acceptance, production, spending, feature implementation or publication authority.
Do not invoke a paid live worker. Follow the actual installed stage skills and their evidence rules.

Use the existing full proxy intake. Preserve its marker, draft status, simulated-answer disclosure
and original input hashes. Run from that consumer root:

`python .specify/extensions/program-kit-governance/scripts/proxy_bootstrap.py prepare`

Preparation reuses the existing pinned schema-runtime installer for the installed engine's Python,
in the disposable project's cache. It does not change the global Python environment.

Then run `proxy_bootstrap.py advance` using the same installed script path. The native engine runs
the installed workflow and pauses instead of dispatching each coding-agent command or prompting at
a human review gate. Read its returned request. This is same-session work, not an independent agent.
Do not run the ordinary `workflow_lifecycle.py` outer orchestration or remove its proxy guard.

## Producer stages

Read the exact installed skill named by the paused command and its supplied stage brief. The sole
authority substitution in this mode is that the input is a disclosed simulated draft; it remains
draft. Existing schema, semantic, source-research, compatibility and handoff requirements still apply.
Use selected, verified primary evidence. Do not use expected acceptance answers to manufacture output.

For installed Python helpers that need the scoped rehearsal evidence, use:

`python .specify/extensions/program-kit-governance/scripts/proxy_bootstrap.py tool -- <installed-helper-path> <arguments>`

The helper path must be repository-relative under `.specify/extensions`. This wrapper starts no
coding agent. Ordinary document authoring and read-only research can use the current session's tools.
Do not implement consumer features. Preserve actual failures and remediation in the transcript.

After completing a producer's prescribed checks, use `proxy_bootstrap.py respond --note "<what was
done and verified>" --file <artifact>` (repeat `--file` for relevant artifacts), then `advance`.
The response binds evidence; it does not mark downstream validation as passed. The engine executes
those validators and stops on their actual failures. Do not write native run state or step results.

## Simulated review

At a review gate, read the exact packet and its material evidence, explain the consequences and
record a justified simulated decision with `respond --choice approve --note "<review rationale>"`
(use `ratify` at the constitution gate or `reject` when warranted), then `advance`.
Never describe this as the user's review. Records use `approval_mode: simulated-proxy` and are
consumable only inside the bound rehearsal invocation. Technical blockers are not approval gates.

## Stop and report

Stop at a substantive blocker or `rehearsal-completed`. Report stages exercised, simulated questions
and decisions, actual checks, artifacts, observed failures and unresolved limitations. The terminal
step produces a separate proxy result, never ordinary consumer bootstrap-completion authority.
No feature flow follows automatically. Never claim independent live acceptance or unmeasured token
savings. Retain the original intake transcript and all native engine history for review.
