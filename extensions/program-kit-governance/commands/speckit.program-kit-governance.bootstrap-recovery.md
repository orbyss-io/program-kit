---
description: Produce corrective architecture artifacts inside a governed bootstrap continuation.
---

Read the workflow continuation ID, source-run ID and handoff in `$ARGUMENTS`, then this
extension's `references/bootstrap-lifecycle.md` and `references/workflow-resumption.md`.
This command is the continuation workflow's corrective producer. It does not own
orchestration, approval or completion. If invoked outside a workflow stage, diagnose the
current state and direct the human-owned terminal to the supported
`workflow_lifecycle.py resume --run-id <derived-run-id>` entrypoint. Never launch nested
workflow workers from an ordinary agent session; only the authorized live harness has a
separate exception for its disposable repository.

Invoke the bootstrap-closure instructions against the existing first slice. Own every filename,
ID, manifest, target and placement decision. Preserve immutable intake/assessment, Accepted ADRs
and ratified constitution. Use scoped follow-on decisions for changed design authority. Do not
remove a retained condition or change NOT READY to READY to make validation pass.

Produce corrected ledger, scoped decisions, acceptance scope and architecture narrative.
Reuse valid compatibility receipts and preserve failed-attempt evidence. Stop after reporting
the produced artifacts and bounded blockers. The engine executes synchronization, review,
human approval, readiness evaluation and completion in order. Do not invoke standalone
repair acceptance/completion commands or ask the user to run them. Old approval does not
approve future changed architecture. Never ask product users for mechanical bookkeeping.

A valid non-ready assessment preserves evidence and reports corrective work. Malformed
output is a producer defect; missing/stale authority is a governance correction. None means
the user rejected the approved architecture. Escalate a new supported-path defect with its
exact command, streams and state. Never hand-edit state.json, skip validators or restart intake.
An installation check, schema pass, repair helper or independent completion JSON is not
proof of workflow success. Completion requires valid project authority and a bound native
workflow-engine outcome of completed.
