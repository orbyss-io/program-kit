# Initial semantic coding families

F5 extends the existing responsibility/source registry and composer. Each
`seed-*` unit resolves its canonical owner and linked manual recipe/checks.
It is not a second selector, rule inventory or claim that arbitrary source obeys
the guidance. Actual named checks, source review and consumer review retain their
separate scopes. F3 qualification still binds actual inputs and evidence; manual
editing cannot waive mandatory context, invariants or checks.

| F5 family / unit | Reused owner and focused outcome | Historical disposition and proof limit |
| --- | --- | --- |
| Modular ownership / `seed-owned-slice` | Native roles/compiled edges, canonical modularity and evidence Core/runtime/API/provider slice | F4's boundary repair is preserved. Structural checks do not certify business ownership; source review covers mixed roles, peer implementations and cross-operation helpers. |
| Thin transport / `seed-thin-transport` | Existing typed JSON/HTTP owner; independently executable application plus real mapping | Plain status results can correctly fail the selected JSON guard. Use admitted problems, not a bypass. Business decisions/provider calls in API helpers remain review findings. |
| Events / `seed-independent-events` | Current native dispatcher feature, registered independent typed handlers, awaited/cancelled/faulted publication, missing registrations and a query exclusion | Existing events were not missing. | Activation / `seed-service-activation` | Actual owning feature registration, root/shell/request boundaries, options admission, scopes/disposal and native success/denial/fault middleware | New fixture discovery/ordering failures are retained. Graph metadata and root-only validation cannot substitute for these assertions. Existing native Tasks fixture covers initialization/workers/drain. |
| Browser / `seed-browser-journey` | Native UI/theme/feedback and selected browser modules in a normal evidence journey; responsive screens, focus, errors and actual controls | Gallery-only evidence is insufficient. Version/profile mismatch and unsupported adapters remain explicit. No second generator, token compiler or branding owner is introduced. |

The full family scope is implemented through one connected fictional journey plus
focused scenarios. Use the single maintained validation inventory for exact IDs,
prerequisites and budgets. `--suite Affected` is explicit for focused groups; the
default Integrity aggregate remains 60 seconds. F4's 986.955-second native run still
exceeds its original 300/600-second limits and is not repeated or relabeled here.

Run `python tests/evidence_review_fixture.py --review` for retained connected
output after preparing its exact selected project-local browser tools; use the
maintained check for bounded execution. The guide links actual source, native
assertions, generated types/client, SQL, streams and desktop/mobile screens.
`--native-only --mutations` supplies separately attributable invalid controls.
Keep every review consumer, failure and snapshot until the human finishes review.

The `evidence-submission` recipe is deliberately a fictional manual example. Its
F3 declaration in the retained consumer demonstrates scoped current qualification,
selection, unrelated exclusion and stale-input rejection. Routing output retains
`applicationObserved: false`; actual application execution is separate evidence,
and agent consultation/obedience is not inferred. F6 teaching/adoption, F7 general
completion evaluation and F8 packaged adoption remain their later items.
