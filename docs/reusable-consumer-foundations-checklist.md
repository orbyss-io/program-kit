Final bounded corrections are in `eng/foundation_qualification.py`'s template, `tests/fixtures/reusable-foundations/qualification.mjs`, `tests/validate_foundation_setup.py` and `tests/qualify_reusable_foundations.py`. The qualifier scopes `PROGRAMKIT_NPM_CACHE`/`NPM_CONFIG_CACHE` to each consumer's `artifacts/cache/npm` and `PLAYWRIGHT_BROWSERS_PATH` to `artifacts/cache/profile/local/ms-playwright`. It restores exact parent values on failure/success, leaves repository inventory commands unchanged and refuses an acquired cache for a cold phase. Its outer failure message admits only known stage/code labels and numeric exit values; missing, invalid, stale or ambiguous metadata produces fixed `unknown`. CI also offers a manual `qualify_reusable_foundations` route through the maintained runner, including composition/setup prerequisites. The default remains `full`, automatic PR/push coverage is preserved, unknown selections fail closed, and targeted checks cannot create a Release receipt or replace mandatory full gates. All 13 routing/semantic-boundary tests pass, including missing/duplicate shared inventory, full-coverage erasure and unknown-selection rejection. The Release receipt and publication-order assertions remain strict. On a non-Windows runner, browser installation adds `--with-deps` only when `GITHUB_ACTIONS` is exactly `true`; this CI-ownership input is declared and hashed, with absent/false/true fingerprint invalidation covered. The CI-scoped repair still requires actual Linux qualification. No diagnostic upload rules were changed.
