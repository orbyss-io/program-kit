# Provider handoff audit and actual proxy rehearsal

## Outcome

The missing provider context and misleading consumer-question path are repaired in
Program Kit. The authorized same-session intake-through-bootstrap rehearsal used
real native validators, shared package restores, published containers and Chromium.
It has **not completed bootstrap**: a real Foundation 0.2.0 OIDC scope-binding defect
blocked login against the selected Keycloak provider. The failed consumer from run
`e2b2e42d` was not patched. No independent paid coding agent or real approval ran.

## Efficiency and mistakes retained

This was an investigative rehearsal with source repairs, not a clean fresh-install
acceptance pass. Initial authoring mistakes in architecture scope/ID and roadmap ADR
evidence were caught by validators. Fixture development also needed corrections:
the read-only feed's extraction mountpoint, required synthetic assurance policy,
the publisher's `/api` challenge contract, and local HTTP cookie expectations.
Scratch-only command diagnostics initially disappeared on cleanup; bounded diagnostics
now reach the coordinator's sanitized preserved streams. An activation-value hypothesis
was disproved using exact upstream CShells source; no generator workaround was made.
These were real avoidable costs, not hidden successful steps.

The new fixtures centralize that verified integration knowledge so ordinary bootstrap
agents do not reconstruct it each time. A failed login HTTP response now fails promptly
instead of first waiting for a nonexistent username field. No reliable isolated token
or cost total exists for this same-session adapter, so no token saving is claimed.
Future comparison must measure token totals, rereads, retries, useful versus avoidable
elapsed time, and first-slice quality in a fresh consumer.
