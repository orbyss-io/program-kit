## Directly inspected evidence and limits

- `extensions/program-kit-dotnet/scripts/composition_model.py` enumerates resource and binding kinds. Shell settings are restricted to the selected infrastructure policy fields; `privateFiles` supplies an owner/host/shell/feature binding with bounded section/setting names and foreign-placement checks. Its filesystem environment adapter is qualified only for Development/Test. No general feature scalar or secret-reference binding is present in these inspected declarations.
- `extensions/program-kit-dotnet/scripts/composition_render.py` builds shell configuration from the selected web, database and hosted-pages composition and validates it against captured settings metadata. This supports the reported gap in this authoring route; it does not prove every native Host configuration mechanism lacks an appropriate seam.
- The consumer's current `PolicyOcrDeployment.cs` uses a bound admission root, Development/Test restriction, absolute non-UNC path checks, directory/file reparse-point checks and a stated 16-KiB input bound. Missing input supplies no grant. Typed source defines endpoint/key/grant inputs; no actual admission document, credential or private upload was read by collection.
- Ownership/recovery/concurrency/partial-output/cleanup regressions are reported passing. They were not executed or independently inspected as final source-bound records here. The paid application call and complete delivered outcome remain unestablished at this check.

The private-volume workaround uses an existing supported placement mechanism and avoids editing managed output or committing secrets. It is not by itself proof of credential privacy, immutable admission, a complete secret lifecycle or correct spending authority. A file-length check before `ReadAllBytes`, path checks and a comment asserting privacy do not alone prove bounded race-safe reads or effective ACLs. Qualify those properties if this adapter is retained; no exploitable race or actual credential exposure has been reproduced here. Keep provider credentials and human operation grants conceptually distinct even if a deployment document carries both: possessing a key cannot authorize spending, and configuration reload cannot renew an already consumed attempt.

## Proposed shared repair and closure

First discover the selected public/native configuration and secret-reference seams and exact feature metadata. Prefer a thin maintained binding to an existing qualified seam. Extend composition only for the actual missing supported scope, with explicit owner/feature/shell/environment placement, authoritative metadata/type/required-value validation and redacted readiness. Preserve the fixed infrastructure policy restrictions; do not expose arbitrary configuration overrides or serialize resolved secrets into generated shell JSON, graph files, evidence, hashes of low-entropy secrets or logs.

Define supported secret-source ownership, loading/rotation/revocation and missing/unavailable behavior. A reference is not a credential value. Qualify effective runtime identity/access, read-only deployment where appropriate, bounded reads and actual refresh/snapshot semantics. Development/Test private-file support must not silently become a production secret-store promise. Configuration updates must not rewrite human authority, consumed grants, durable reservations or uncertain operations.

Central installed synthetic coverage should demonstrate a metadata-declared feature scalar and a secret reference through the actual model, renderer, preparation, native registration and runtime activation. Reject unknown keys, wrong types, missing required references, foreign placement and attempts to override protected infrastructure settings. Include privacy canaries across generated files/readiness/errors and missing, changed, denied or stale secret-source cases. Preserve existing private-file consumers and normal update behavior. Report actual supported environments and source-bound execution; mocked generation alone cannot establish runtime binding or secret protection.

Consumer test-helper ordering and missing graph bindings were reported agent setup errors corrected without suppressing analyzers or gates. They do not supply another defect ID. No product code, consumer state, installation or release state was changed by this assessment.
