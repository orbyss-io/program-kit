## Supported happy path

After normal-shell initialization/install, invoke
`$speckit-program-kit-governance-product-intake` in the current session. The native command source
is [product-intake](../../extensions/program-kit-governance/commands/speckit.program-kit-governance.product-intake.md);
Spec Kit generates the installed SKILL.md. The old bootstrap command is a thin alias.

The skill starts from a rough idea or a developed design, researches consequential meaning, grills
contradictions, discloses applicable defaults and preserves explicit/provisional/unknown provenance.
It authors connected product intent/journeys, constitution, consequential ADRs, technology radar,
outcome epics/features, canonical domain/C4 map and relevant qualified selections. Functional
understanding includes important identities, roles, lifecycles, policies and cross-context effects;
feature intake deepens future detail. No exhaustive future design or stage dossier is required.

Use [focused founding](../../extensions/program-kit-governance/references/product-founding.md) for
exact paths and commands. Intake confirmation is separate from constitution ratification. Then:

```text
python .specify/extensions/program-kit-governance/scripts/product_intake.py defaults
python .specify/extensions/program-kit-governance/scripts/product_intake.py review
```

After reviewing exact named artifacts and receiving explicit human founding acceptance:

```text
python .specify/extensions/program-kit-governance/scripts/product_intake.py accept --verdict approve
python .specify/extensions/program-kit-governance/scripts/product_intake.py validate
```

Continue directly to `speckit.program-kit-governance.specification-intake` for the selected first
feature. Candidate/non-Ready or missing roadmap entries do not prohibit useful feature intake.
The existing intake frontier is projected into feature review and retained due decisions remain
checked by the normal phase owner. No new ledger is introduced.
