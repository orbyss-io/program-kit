[Raw samples](../../artifacts/f6-review-20261018/performance.json) bind SDK
**10.0.402**, runtime **.NET 10.0.13**, Windows x64, 32 reported processors and
Release. These medians summarize all five raw rounds, not a universal speed claim:

| Operation | Median milliseconds | Managed allocated bytes |
| --- | ---: | ---: |
| 256 scan lookups | 6.5179 | 577,576 |
| 256 indexed lookups | 0.0186 | 10,280 |
| Index construction plus one lookup | 0.2314 | 218,240 |
| Scan construction plus one lookup | 0.0509 | 67,840 |

The index improves this repeated workload and costs more preparation/allocation for
one query. Grouping storage/copies remain an adverse tradeoff. Thread-local managed
allocation is not retained heap or process RSS. Original input mutation does not
update an old snapshot; rebuilding produces the new result. This is neither a live
store/database optimization nor a universal rule. No timing threshold manufactures
correctness or performance acceptance on another runtime/workload.
