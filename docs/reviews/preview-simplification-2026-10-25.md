# Preview simplification review — 2026-10-25

This implements the approved second simplification pass from source 237fba6 on the
existing contribution branch. The direction is native Spec Kit phases enriched with
relevant, extensible knowledge and convenient optional engineering automation.

Agreed human review points remain real boundaries. Discuss them before implementation,
make them visible in normal plans/tasks, and obtain the human decision before dependent
work continues. The replacement does not infer acceptance from files or tests. It removes
the separate bookkeeping protocol used to permit ordinary work.

Inspect the native preset and phase commands for appended guidance and normal tasks,
the product/specification intake skills for readable human-reviewed artifacts, and the
architecture helper for a small language-neutral domain/C4 map. Review the absence of
hash-bound authoring approval/confirmation and hidden task checkpoint requirements.

Knowledge use is independent of optional automation. A selected scaffold, build or
composition helper still validates the actual contracts required for that operation.
A failing build/test, unresolved consequential choice or agreed review remains meaningful;
whole-application runtime startup is not a universal entry requirement for coding.

The 0.x-to-preview boundary is explicit re-onboarding, using selected existing architecture
files as input. Old workflow state is not translated into new authority. Preserve authored
software, native Spec Kit artifacts, ADRs, locks, customizations and immutable historical
release bytes. Subsequent previews preserve ongoing authored work. A later break needs
explicit notice. The current release version becomes 1.0.0-preview.1 across metadata and
initializers. Preview publication classification and exact-byte approval remain separate
from this source implementation; no tag or publication is authorized.

Validation replaces removed engine-state requirements with outcome checks: native command
preservation and knowledge additions; an independent technology stack; ordinary spec/tasks;
visible agreed review instructions; useful content/schema failures; selected optional
engineering behavior; archive-native installation; preview classification and safe toolkit
replacement. Old state-format tests are retired where their product contract was removed;
actual engineering, distribution integrity and privacy safeguards retain their owners.
Deterministic fixtures use synthetic products and simulated review text. They establish no
actual human acceptance, agent obedience or private consumer outcome.

The maintained replacement checks are `validate_native_phases` (native command preservation,
ordinary tasks and focused knowledge), `validate_readable_founding` (readable documents and
small-map negatives), `validate_minimal_map_selection` (optional generator integration),
`validate_preview_distribution` (versioning, safe replacement and retired payload boundaries),
and the six representative mechanical families. Existing schema, compiler, source ownership,
package installation, security and dependency checks remain independently selected.
Tests whose entire contract was hidden task history, approval fingerprints, bootstrap proof
promotion or automatic 0.x authority migration are removed from the current inventory. Frozen
historical source witnesses remain data; their existence does not require shipping old engines.

The preceding source's package CI 40181852418 passed build, Windows/Linux installation,
security and timing jobs. The new source needs its own package CI. Local validation
commands, streams, actual content identities, failures, costs and coverage limitations
