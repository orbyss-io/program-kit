# Implementation increments and native EF review

The agreed outcome is a clearer small engineering loop and a maintained upstream analyzer repair.
Only synthetic fixtures are used. No consumer files, pins, authored code or data are changed.

## Guidance changes

- Native tasks name an observable increment, actual dependencies and a useful focused check.
  Large task counts are not progress percentages; settings grow with their first consumer.
- Foundation composition adoption is an explicit first engineering increment around the first
  operation, without requiring a separate spec, approval receipt or supplier-wide requalification.
  Realm/login and database/provider checks apply only to the selected resources and product boundaries.
- Implementation distinguishes an expected behavioral red test from an unexpected setup failure,
  compiles the first small integration, reuses unchanged evidence and continues until a real blocker,
  completion or an agreed human review. Safety requirements remain prerequisites for readiness.
- Resume guidance reconciles current operative tasks with accepted changes, retaining IDs, completed
  work and linked history. It does not regenerate consumer tasks or edit through read-only Analyze.
- Provider-test discovery links directly to actual shell activation and native unit/context ownership;
  a focused database fixture does not require the complete Host/Keycloak/browser topology.

Inspect the native preset appends, composed tasks template, implementation-check command and the
PostgreSQL example README. `validate_native_phases.py` retains actual installed/resolved output for
review. Deterministic instruction inspection establishes packaging/coherence, not future agent behavior.

## Upstream and adoption

Foundation owns the independent analyzer release and its native EF declaration-layout contract.
The analyzer accepts native relational builder declarations in real Migration.Up/Down overrides,
without generated headers or whole-file exclusions. Authored helpers, local functions, arbitrary
calls and control-flow remain checked. The original EF/tool 10.0.13 and current publisher pins have
separate generated-code regressions; no operations, designer or snapshot are rewritten.

Program Kit's bounded `update_dependency_profiles.py prepare --tool Orbyss.Foundation.Analyzers`
discovers only that tool. Normal native qualification, public archive/provenance binding, publisher
capture and promotion own adoption. Historical profiles/locks remain unchanged. Unchanged Forms
evidence may be explicitly retained with its original execution scope; it supplies no new browser run.

`validate_private_ef_metadata.py` now compiles the raw generated migration unchanged, verifies hashes,
rejects authored work with ORB1008, checks drift and SQL, packs/stages a genuine private-EF feature,
deploys through native EF and activates it on the selected published Host. Candidate archive runs are
development evidence. Completion requires independent restoration and the same proof with the new
public analyzer, followed by installed-output review and focused affected validation.

## Review limits

The native database/Host fixture establishes its synthetic operation and least-privilege boundaries;
it does not establish real login, browser or consumer product acceptance. Existing supplier login
evidence is reused only within its declared unchanged scope. Product storage/fencing implementations
are not supplied by these guidance changes. Human story review and deployment authority remain real.
