The completed human trial `76d8b67f` exposed two bounded kit defects. The review is
in `consumer-trial-review-76d8b67f-2026-09-18.md`. This repair preserves that consumer
and its recorded approvals, proof receipts and outstanding implementation obligations.

## Managed identity projection

The approved register contained `Keycloak`, while provider projection dispatched only
on lowercase `keycloak`. Projection now recognizes the known managed identity
case-insensitively, with surrounding whitespace ignored. It preserves approved text
and still requires `local-evaluation` scope. Unknown providers and consumer-service
deployments do not acquire managed pins. Existing missing/unpinned-image failures remain.

A read-only replay against the unchanged completed consumer now projects its managed
Keycloak 26.7.3 image and digest. This supplies previously omitted proof inputs; it does
not claim that its BFF/Keycloak compatibility proof has executed or passed.

## Authored versus generated bytes

Stage sizing reports authored, generated and total UTF-8 bytes separately. Existing
hard budgets apply to authored content. Only an exact canonical lifecycle, roadmap or
quality-case view is excluded: arbitrary prose inside markers stays counted. Duplicate,
incomplete or reversed markers are rejected. Physical CRLF and Unicode byte accounting
is preserved. JSON and DSL limits still count the complete artifact.

The terminal bootstrap validator uses the same accounting for the three synchronized
narratives. Approval already synchronizes lifecycle views before its final validation.
Stage commands direct agents to the supplied sizing command instead of improvised
whole-file byte assertions. Quality cases remain complete in their generated view.
