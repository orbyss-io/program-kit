# Story delivery amendment (pending publication)

This development change is not available in the published predecessor. Candidate version selection,
dependency maintenance and publication remain separately authorized gates. When released, the
installed `references/phase-evidence.md` supplies the workflow/transition and adoption contract.

The amendment delivers coherent runnable stories and required human review per story. Internal
operations progress without repeated human pauses. Required story/explicitly agreed early reviews
pause further product work; acceptance or bounded named deferral permits only its scope. Deferred
reviews remain due before feature acceptance. Engineering completion, time and silence never grant
human acceptance. Optional GitHub linkage uses confirmed verified accounts and authenticated exact
decision references, without posting or monitoring. Active effort warnings at 60 operation minutes/
120 story minutes are advisory, include repairs and survive resume.

Known scaffolds are materialized coherently first, then maintained generation/configuration/build/
integration checks and missing consumer-specific tests. Verification remains mandatory and selected
by risk; critical/uncertain behavior and reproducible bugs prefer meaningful test-first checks.

Existing unfinished features require a fresh start:

1. Checkpoint/archive the abandoned attempt and failed evidence.
2. Install the released toolkit through the normal supported updater.
3. Preserve unchanged confirmed bootstrap/intake, accepted architecture, foundations/tooling,
   consumer locks and previously delivered features.
4. Amend the constitution to replace universal test-first sequencing and adopt story review,
   authority, progression and advisory effort. Use the existing reviewed ratification mechanism.
5. Review/select a concrete owned reset inventory. Shared source/generated outputs, migrations and
   data require clear ownership. `task_draft.py reset` previews a bounded file-only inventory;
   apply requires an explicit exact human selection and archives bytes before removal. It does not
   reset shared code, migrations or live data. Real consumer reset needs separate session authority.
6. Abandon old spec/plan/tasks/code/tests as active work; retain history. Partial code and checked
   tasks cannot become new progress.
7. Rerun specify, clarification, plan, tasks, analysis and implement. Run configured hooks once at
   their owning boundaries; absent hooks use the same maintained entry/finish checks explicitly.
   Reuse confirmed intent without restarting the product interview.

Qualification is deterministic workflow/state coverage and one installed disposable reset exercise.
It establishes no real human acceptance or coding-agent delivery-speed claim. Installation/recovery
and publication coverage remain. Before publication: select version and register this amendment in
versioned release/consumer-change metadata, complete dependency update/profile/knowledge work,
freeze candidate, obtain fresh successful local Release evidence and green CI, then complete tagged
Release and public install/upgrade. Firefox remains in CI; local Release follows the human-terminal rule.
