# Program Kit 0.13.0

This release delivers small runnable user stories with persistent human review,
risk-selected verification and fresh-feature adoption. It applies to new features
and unfinished features adopting the amended constitution. Installation preserves
consumer source and locks; it does not reset a feature or establish human acceptance.

## Delivery and review

Plan actor outcomes, walkthroughs, effects and useful story boundaries. Internal
operations progress without a human pause after every operation. Required story
reviews and explicitly agreed early checkpoints pause further product work by
default. Only actual acceptance or an explicit, named and bounded deferral permits
its scope. Deferred reviews remain due before feature acceptance and formal handoff.
Engineering completion, elapsed time and silence never grant human acceptance.

Reviewer assignments, decision provenance, implementation and outcome freshness,
pending decisions and failures persist through resume. Material changes reopen
affected reviews. Optional GitHub linkage requires a verified account and confirmed
assignment; explicitly supplied exact decision references are authenticated and
validated for author, source and scope. The toolkit does not post or monitor decisions.

Materialize known scaffolds coherently first, then run maintained generation,
configuration, build and integration checks and add missing consumer-specific tests.
Verification is mandatory and selected by risk. Critical or uncertain behavior and
reproducible bugs prefer meaningful test-first checks; universal test-first sequencing
is replaced. Default active-effort warnings are 60 minutes per operation and two
hours per story, include repairs and survive resume. Waiting and stopped sessions
are excluded. Time alone never blocks implementation.

## Adoption and required human decisions

For a new feature, ratify the amended constitution and run the normal fresh Spec Kit
phases. Existing completed features require no reset or retrospective story review.
For an unfinished feature adopting this release:

1. Checkpoint/archive the abandoned attempt and preserve failed evidence.
2. Install 0.13.0 through the supported resumable updater, after reviewing its plan.
3. Preserve unchanged confirmed bootstrap/intake, accepted architecture, foundations,
   tooling, exact consumer locks and previously delivered features.
4. Amend the constitution to replace universal test-first sequencing and adopt story
   review, authority, progression and advisory effort. Review and ratify through the
   existing hash-bound constitution mechanism.
5. Review/select a concrete exclusively owned reset inventory. `task_draft.py reset`
   previews bounded feature files; apply requires exact human selection and archives
   verified bytes before removal. Shared code, migrations and live data require their
   own ownership and authority; this helper does not reset them.
6. Abandon old specification, plan, tasks, partial code and tests as active work.
   Retain history; partial implementation and checked tasks cannot become new progress.
7. Rerun specify, clarification, plan, tasks, analysis and implement from a fresh
   specification. Reuse unchanged confirmed intent without restarting the interview.
   Run hooks once at owning boundaries; no-hook paths invoke the maintained entry,
   resume, finish and formal handoff checks explicitly.

Real consumer reset and external rollout need separate consumer-session authorization.
Installation alone grants neither. Supported exact dependency selections remain valid;
adopting a new qualified default requires the existing reviewed dependency transition.

## Verification and recovery

Inspect installed canonical guidance, projected context, resolved commands and runtime
checks together. Exercise changed product behavior independently of structural checks.
Required reviews must be current and accepted at feature closure and formal handoff.

Deterministic qualification covers story authority/freshness/progression/clock controls
and one reset exercise within the existing installed-consumer fixture. Installation,
source protection, activation/recovery and public publication checks remain maintained.
These fixtures establish no real human acceptance or coding-agent delivery-speed claim.

Retry the same verified updater after repairing a reported failure, preserving sealed
original inputs and failed evidence. Preserve abandoned archives and resume from the
fresh adopted feature; never relabel partial work as accepted progress. Git or toolkit
recovery cannot undo live service, identity or database changes. Local Windows uses
Chromium/WebKit; CI retains Firefox. Publication requires dependency maintenance,
fresh local Release evidence and the complete tagged workflow with public install/upgrade.
