# Program Kit 0.12.9

This patch makes existing engineering knowledge reach the decisions that need it,
adds ordinary reviewed feature-plan resolution, and delivers the consumer contract,
intake, UI and verification improvements prepared since 0.12.8. The separate
architecture refresh/evolution investigation is not part of this release.

## Knowledge and normal development

Before-plan guidance uses scoped adopted targets, compositions and technology as
well as feature prose and selected files. It does not inherit every neighboring
owner's private capabilities. Essential conditions, prohibitions and exceptions are
read directly from canonical references; examples and detailed sections remain
focused lookups. All 34 maintained references have explicit usage and enforcement
routes, including manual and maintainer-only knowledge.

Affected .NET designs declare meaningful responsibility names, kinds, effects and
provided capabilities in eng/architecture.json. Checks reject declared Core/runtime
contradictions and missing capability bindings. Pure policies and empty initial graphs
remain legitimate. A declared or compiled graph pass establishes structure; actual
responsibility placement, composition behavior and governing authority still require
their normal tests and semantic review.

After normal design review, retained feature-plan decision prerequisites can bind
their exact reviewed sections through feature_plan_decisions.py. Native eligibility
and implementation preflight consume the same scoped records without rewriting the
approved bootstrap ledger or intake. Changed sections reopen their dependent decision.
Compatibility, delivery and governing-authority prerequisites retain their actual
evidence and due phase. A plan cannot discharge executed proof or approve a new ADR.

Engineering reports distinguish command execution, structure, behavior, semantic
review and human acceptance. The old verify-delivery writer is retired; historical
dossiers remain inspectable and do not become ordinary development prerequisites.
Roadmap status is consumer-owned status rather than a new test receipt.

Implementation uses focused/affected verification during progress and complete
engineering acceptance at closure or formal handoff. Saved tasks and resumes preserve
completed work; generated context and test execution do not create new approval gates.

## Consumer contracts, intake and qualified dependencies

Application receiver handoff includes source-bound settings, component/API bindings,
delivered documentation and an independently verifiable archive. Missing publisher
coverage stays explicit. Native build, host/public availability, contract compatibility
and actual consumer behavior remain separate from archive integrity.

Functional discovery and informed intake improve product questioning. Optional proxy
intake/bootstrap remains simulated, non-authorizing draft work and does not authorize
implementation or paid workers. Modern UI/authentication patterns improve the existing
UI experience profile while retaining its security and accessibility requirements.

The qualified default adopts published Foundation 0.3.1, Build 0.3.1 and exporter 0.2.5.
Historical qualified profiles and exact existing consumer pins remain preserved.
The maintenance workflow updates active external pins, locks and qualified publisher
knowledge together; lookup, deterministic validation and security failures block it.
Spec Kit CLI 1.1.1 is the current tested baseline. Human-owned infrastructure inputs
and outer workflow launch remain explicit boundaries; no agent permission bypass is
introduced by this patch.

## Upgrade from 0.12.8

Use the verified release-owned updater's --plan mode, inspect the cumulative migration,
then install through the maintained updater. Verify installation coherence and exact
retained dependency inputs. Managed toolkit instructions/helpers are updated; consumer
plans, tasks, code, accepted ADRs, ratified constitution and bootstrap approval history
are not automatically rewritten. Existing dependency locks are not silently promoted
to the new default profile.

Resume the normal feature command after installation. Review missing responsibility
metadata only for the affected design, and record actual reviewed feature-plan
resolutions in the normal plan. Do not fabricate review provenance, closure records or
passing history. A substantive change to governing architecture or product intent still
uses its existing governed review path. Installing this patch alone does not require
bootstrap restart, renewed product intake, a constitution amendment or data migration.

Existing receiver handoffs and settings metadata remain consumer-owned. Refresh their
affected configuration and real verification when using the new handoff capabilities;
installation is not application delivery acceptance. Adopting different dependency
versions remains a separate reviewed transition.

## Validation and recovery

Regressions cover adopted context before projects exist, canonical constraints across
phases, the mixed-Core/runtime case, omitted bindings, valid minimal designs, scoped
plan resolution/staleness, unchanged approved history, retained execution gates and
truthful reporting. Installed-consumer and archive checks exercise the actual shipped
helpers and instructions. Publication requires fresh local Release evidence and the
complete tagged Release workflow, including Firefox and public installation/upgrade
checks. The deterministic suites start no coding-agent sessions.

Preserve failed updater, validation and workflow evidence. Retry the same verified
updater or resume the existing feature draft; correct the diagnosed affected inputs.
Do not invoke the retired delivery writer or rewrite historical hashes to imply current
acceptance. A real governing-authority change still follows the existing maintenance
route; the broader architecture refresh capability is reserved for a later patch.
