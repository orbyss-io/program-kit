# Program Kit 0.14.3

This candidate closes guidance and review gaps that allowed source rules and effect
responsibilities to disappear between planning, task authoring and implementation.
Complete canonical constraints arrive before coding. Existing operation maps record
concrete decisions and first coherent check owners; current source-scoped evidence and
independent review cover applicable effect, trust and lifetime responsibilities.

## Existing consumer action

Use the supported isolated updater and review authored customizations. Retain original
intent, task IDs/checkmarks, baseline/effort, prior failures, source/data, frozen
migrations, selected profiles/locks and accepted human decisions. Update affected
spec/ADR/plan/tasks in place. Do not restart an unfinished specification to adopt this
contract.

Before affected coding, resolve ownership and result meaning, then applicable shared
deadline/cancellation, cleanup and uncertain effects, transaction/replay, admission,
bounds, configuration/time and activation/drain responsibilities. Select compatible
maintained patterns, adverse cases and the first coherent check. Inspect accessible
facts locally; ask the human only for missing consequential intent, architecture,
risk, data or authority decisions. Toolkit gaps belong in the actual producer,
registry, template or validator. Missing environments need a named preparation owner
or capable CI proof; unavailable independent review remains pending.

The candidate default adopts qualified public Foundation 0.3.7; independently versioned
Build/exporter, Forms and Localization pins are retained. C# source work requires an
actually published qualified Foundation analyzer/profile
providing `source-readability-v1` through the selected native policy. Adopt it through
the supported reviewed dependency transition. Toolkit installation preserves existing
consumer locks; an old analyzer build or local unpublished package cannot supply
public profile qualification. Do not suppress rules or disable analyzer execution.

The same existing-source recovery covers explicitly owned nonnative source tasks, including
Python and other supported task-reference formats. Their source review and real behavior
checks do not acquire a Foundation/.NET dependency. Documented source ownership remains
necessary; unrelated repository files and guidance documents do not become repair targets.

At the next affected source entry, use the supplied `conformance-register` request to
insert unique repair prerequisites in existing tasks. Start their operation with
`purpose=conformance`, inspect and refactor all existing owned source against applicable
coding guidance, and run real source and positive/adverse behavior checks. Submit
current independently attributed source findings and outcome assessment through
`conformance-complete`. If a repair changes behavior, use `conformance-amend` to mark
that material change and reopen the affected human outcome review. Preserve original
decisions in history. Refresh current story engineering before dependent product work
resumes. Independent scopes can continue while a consequential decision is unresolved.

## Evidence and limits

Source analyzer checks enforce reliably decidable syntax contracts. Operation maps,
source ranges/hashes and reviewer attribution preserve current scope; they do not
certify arbitrary semantic correctness, authenticate reviewer identity or prove future
agent compliance. Meaningful async, cancellation, cleanup and uncertainty behavior
remains the owning tests and source review's responsibility. Deterministic validation
launches no coding agent and supplies no human product or provider authority.

This is candidate guidance. Qualification and affected checks retain failures, runtime
costs and missing coverage separately. A successful exact-source Windows/Linux package
CI run, native publication approval and actual public installation/upgrade verification
remain necessary before this version is available.
