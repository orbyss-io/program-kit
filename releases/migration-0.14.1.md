# Program Kit 0.14.1

This patch adds an explicit tooling-only route for an existing installation whose
historical application authority has been withdrawn. Publication requires exact-source
package CI, the native `publication` approval and public installation/upgrade verification.

## Upgrade behavior

The paired `--inactive-history` and `--inactive-history-sha256` arguments bind a
reviewed declaration to the unchanged historical selection, authority, confirmed intake,
native dependency outputs, profiles, locks and receipts. Missing observed application
targets remain historical observations. Only owned executable engineering scripts are
refreshed; no composition, application projects, Accepted decisions or replacement locks
are invented. Active architecture retains its ordinary materialization and ownership guards.

The isolated workspace adapter now carries both reviewed inactive-history arguments and
`--local-repairs` / `--local-repairs-sha256` through install, interrupted retry and destination
activation. It binds exact declarations, case contracts and module sources, rejects changed
arguments, and transports only missing review artifacts after checking destination conflicts.
The native updater still authenticates original source and freshly executes required cases.
Completing an operation does not authorize reuse of its old repair declaration against
different installed source. Preserve all original and failed attempt evidence.

Windows preparation can restore isolated checkout newline conversions only when original
bytes equal the exact committed Git blob and every conflict is line-ending-only. Actual
customization still rejects. This changes neither device Git configuration nor source bytes.
The coordination inventory also recognizes the existing exact native UTF-8 transformation;
other core changes remain customizations.

## Consumer recovery

Use the separately verified 0.14.1 package and the maintained workspace adapter. Review the
concrete inactive-history declaration and any source repairs with their exact semantic case
coverage; preview the complete plan before installation. Run current scoped checks, assess
and reconcile the isolated result, review and integrate source, then activate with the same
reviewed arguments and fresh destination checks. See the shipped
`references/consumer-upgrade.md` for the declaration and recovery contract.

An existing local frontend-preparation repair may be explicitly retained with its original
ownership and a pending merge duty. It must be reviewed and qualified before application use.
Installation, scoped tooling migration completion, successor design acceptance, destination
activation and application correctness are separate results. This patch neither reruns the
initializer/bootstrap nor supplies human acceptance or private consumer repair coverage.

Selected dependency profiles, historical qualification inputs and consumer locks remain
unchanged. Dependency maintenance already accepted on `main` retains its own qualification;
this repair adds no unrelated dependency transition. The immutable public 0.14.0 release is
preserved and is never relabelled as containing this patch.

## Validation limits

Deterministic disposable regressions exercise unchanged active guards, hash-bound withdrawal,
preservation, real packaged component replacement, managed-conflict interruption, fresh local
case execution on retry, and workspace transport/recovery. Review authoring is fictional.
These checks do not establish application behavior, real consumer activation, provider/browser
compatibility or coding-agent acceptance. Native ownership runs in the publisher Git checkout
can exceed their time bound when rejecting deliberately changed sources through Git-history
fallback; those unfinished runs remain failures. The separate extracted-source ownership
matrix and exact-source package CI retain their actual outcomes. A native evaluation journey
completed functionally at 121.6 seconds against a 120-second budget and remains over-budget.
