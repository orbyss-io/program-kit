# Program Kit 0.14.0

This minor release delivers the approved F1–F8 coding system and the repository-scoped
Program Kit development skill. Availability requires successful exact-main package CI,
native GitHub `publication` approval, and actual public installation/upgrade verification.

## Delivered behavior

- Canonical knowledge discovery connects source rules to applicable coding units.
  Coding preparation composes actual task, architecture, selected dependencies and
  source ownership; reconciliation checks the resulting change.
- Shared and private consumer patterns support explicit qualification, alternatives,
  refinement, retirement and bounded learning. Private evidence is not promoted upstream.
- Safe scaffolds preserve authored customization and reject ownership conflicts.
  Current evaluation checks applicable duties and evidence at engineering completion;
  historical success or status-only JSON cannot establish current proof.
- C# composition-preset projects and their peer-reference exception are retired.
  Owning features register services; shell/deployment configuration selects features.
  Existing affected graphs require explicit owner review and repair, not silent rewriting.
- The contributor `program-kit-development` skill stays under this repository's
  `.agents/skills/`. Consumer archives do not install it.

The selected Foundation runtime 0.3.6, Build 0.3.2 and Exporter 0.2.7 remain the approved
dependency set. Historical profiles, captures and existing consumer locks are retained.
This release preparation does not perform unrelated dependency upgrades.

fresh F8 installed journey completed functionally in **126.204s against a 120s budget**;

human-operated session completed 11 tasks with explicit human approval, within that
scenario's scope. It is distinct from the existing-consumer trial. Deterministic authoring/reviews
and simulated decisions remain labeled; hashes do not prove semantic truth or general
agent obedience. The development skill has bounded small-edit, seeded-bug and substantial
investigation exercises; it has no general productivity or full-feature-delivery proof.

provider observations retain their exact scopes. Package CI checks integrity, one build,
Windows/Linux installation/entrypoints and applicable security; it does not establish
complete behavioral, browser, provider or coding-agent acceptance.

## Recovery

Preserve source, packages, logs, hashes and consumer evidence before any recovery.
There is no automatic downgrade from 0.14.0 to 0.13.x. Deleting a GitHub release does
not downgrade installed consumers or erase other publication destinations. The preserved
`maintenance/0.13.x` branch begins at successful v0.13.3. Future 0.13.x publication must
still reach an exact reviewed `main` commit and pass the maintained CI/approval workflow.
See the repository's `docs/maintenance/withdraw-0.14.0.md` for the concrete withdrawal
and maintenance route. A successful withdrawn version is never reused for different bytes.
