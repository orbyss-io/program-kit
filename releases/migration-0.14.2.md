# Program Kit 0.14.2

This patch addresses [issue #51](https://github.com/orbyss-io/program-kit/issues/51):
implementation-shaped repair assessments and destination activation after a reviewed
source merge carries tracked toolkit files and generated skills.

## Upgrade behavior

Before selecting repair dispositions or required cases, establish the repair's purpose
and original applicability, inspect current consumer use and the exact candidate's
supported mechanism, then classify it as required, replaced, obsolete or uncertain.
Test the applicable outcome. A local BuildVersion/scoped wrapper need not survive when
fresh release build, test and pack already receive VERSION and no current caller needs
the old API. Real outcome loss remains blocked. This guidance does not establish why
an original local patch was authored or prove future agent compliance.

The maintained workspace adapter captures candidate installation inputs separately
from consumer source. Reviewed tracked setup may arrive through Git; ignored setup
must match the original baseline. Before destination installation it archives the
actual destination and projects complete original native sources, registries, outputs
and genuine generation history. The ordinary forward updater retains its admission
guards. Consumer intent under .specify/memory and other non-native setup is preserved
and checked after installation. Failed activation restores exact pre-activation setup;
the reviewed source merge remains consumer-owned.

## Consumer action and recovery

Use the verified 0.14.2 release's workspace adapter and repeat integration review before
activation. Older review records lack the candidate installation inventory and require
fresh review; do not invent it. Reassess an existing failed activation from its retained
evidence and use the maintained recovery command before selecting a coherent baseline.
Do not restore only part of .specify, pair old source with candidate skills, fabricate
generation history, or modify a public archive to bypass native ownership.

Missing original generation provenance uses the maintained forward, no-force native
integration route after ownership/customization review. Fresh generation supplies no
fictional historical authority. Installation, scoped behavior, applicable migration,
destination activation and human/application acceptance remain distinct.

Existing selected dependencies, profiles, locks, authored application work, historical
receipts and failure evidence remain retained. No feature reset, bootstrap restart,
dependency upgrade, worker dispatch or provider operation is authorized by this patch.

## Validation and limits

Windows disposable checks exercise actual historical bundle installation, isolated
packaged upgrade, tracked source integration, native generation, concurrent edit
refusal, retained intent, intended failed destination checks, exact recovery and fresh
activation. The explicit three-install investigation has a 360-second bound; its final
0.14.0-to-local-0.14.1 development run passed in 273.592 seconds. The earlier 324.655-second
run against a 300-second bound remains over-budget evidence. Release candidate version
and package mechanics require their own exact-source CI and installed smoke checks.

Release-wrapper tests observe actual VERSION forwarding and failure propagation with a
fake SDK; they do not prove compiled-package or application behavior. Historical source
witness tests retain complete exact rows while accepting reordered/new release rows,
and reject missing or altered witnesses without changing the catalogue.

Integrity and focused regressions passed locally. An affected native evaluation journey
hit the outer sandbox's Windows service-information restriction; the same retained native
command and full journey passed with normal host access. Original failures remain
separate. Review authorship is fictional. These checks do not establish real consumer,
browser/provider, human or coding-agent acceptance. Exact-source Windows/Linux package CI,
native publication approval and successful public installation/upgrade remain required
before this version is available.
