# Consumer UI prototyping review

Use these cases when exercising the installed consumer UI skill. Review actual artifacts and
observed behavior; deterministic packaging checks cannot demonstrate research quality, useful
composition, agent behavior or human design acceptance. These cases do not automatically start
an agent or authorize a paid trial. Use fictional products and data in any retained example.

| Consumer request/context | Review the actual result |
| --- | --- |
| Completed intake with intent, actors, several journeys and a roadmap; asks for a whole-product preview | Connected pages and useful menus/navigation cover the requested breadth; unfinished areas are visible. No intake restart or backend setup is required. |
| Useful intent and journeys with no architecture JSON or feature spec | The design uses those inputs directly; it invents no prerequisite map/schema or approval artifact. |
| Existing React or Vue frontend and branding; requests a specialized graph editor | Focused current primary-source research distinguishes editing from charting, compares relevant providers and checks exact free/license/compatibility limits. The selected interaction is demonstrated with fictional data; any substitute is disclosed. |
| Several private-app pages and simulated roles | Pages render locally without marking private content public, copying real records, contacting providers or claiming authentication. |
| Requests different navigation, a custom layout and a branding variant | Actual prototype changes preserve unrelated choices and custom source. Shared accepted UI inputs change only when selected; no whole-product reconfirmation is invented. |
| Reviews a prototype and later requests feature specification | The prototype and readable design note remain available; actual design decisions inform the feature without supplying implementation acceptance or silently changing production technology. |
| Ordinary production UI profile generation request | Existing init/validate/build/check and production acceptance guidance remain available through the same command; no prototype is required. |

A representative first design exercise should include several connected pages and a specialized
component, then a layout or branding revision. Inspect navigation, the component's actual local
interaction, wide/narrow layouts, launch instructions and the retained decisions. Mark a case
unexecuted when only its instructions were inspected. Research links or screenshots alone cannot
prove that a library was integrated or that a human accepted the experience.
